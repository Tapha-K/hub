# Frontend PM 우선순위 로드맵

## Summary

- 1차 구현과 시연은 PC 웹 기준으로 한다.
- 목적은 기능 검증과 발표 시연을 먼저 안정화하는 것이다.
- 모바일 웹 반응형과 앱 전환은 MVP 검증 이후 단계로 둔다.
- P0에는 사용자가 빈 상태에서도 바로 시작할 수 있도록 빠른 시작 템플릿을 포함한다.
- P0 데이터는 `localStorage`로 유지하고, API 연동은 P2 첫 항목으로 둔다.

## Priority Backlog

### P0: PC 웹 MVP 화면 골격 + 빠른 시작

- React Router를 도입해 화면 단위 흐름을 분리한다.
- 핵심 화면은 온보딩, 방 목록, 빠른 시작, 방 생성, 방 상세, 세션 타이머, 완료 기록, 내 기록으로 둔다.
- 빠른 시작 템플릿은 다음 네 가지를 기본 제공한다.
  - `30분 조용히 읽기`
  - `15분 짧게 시작`
  - `토론 없이 한 줄 감상`
  - `입문자 환영 방`
- `localStorage`에 닉네임, 방, 세션, 완료 기록을 저장해 새로고침 후에도 흐름이 유지되게 한다.
- 백엔드 없이도 PC 웹에서 닉네임 입력부터 빠른 시작, 세션 완료, 기록 확인까지 시연 가능해야 한다.
- 시연 편의를 위해 샘플 데이터 생성과 데이터 초기화 기능을 제공한다.

### P1: UX 완성도 + 함께 읽는 느낌

- 필수 입력 검증, 오류 메시지, 빈 상태, 완료 상태를 정리한다.
- 방 생성 폼은 제목, 설명, 세션 시간, 토론 여부, 입문자 환영 여부를 받는다.
- 실시간 없이도 함께 읽는 느낌을 줄 수 있도록 누적 참여 수, 최근 완료 기록, 방 감상 수를 보여준다.
- 세션 화면은 큰 타이머, 이탈 경고, 이탈 횟수, 완료 CTA를 중심으로 구성한다.
- 완료 기록 폼은 책 제목, 시작 페이지, 끝 페이지, 감상을 필수로 검증한다.
- 내 기록 화면에는 `14일 내 3회 세션` 목표 진행 상태를 보여준다.

### P2: API 연동

- `VITE_API_BASE_URL` 기반 API client를 추가한다.
- P0의 `localStorage` 데이터 흐름을 Spring Boot REST API로 교체한다.
- 연결 대상은 사용자 생성, 방 목록/생성/상세, 세션 시작, 이탈 횟수 반영, 세션 완료, 내 기록 조회다.
- 로딩, 실패, 재시도, 빈 응답 상태를 화면별로 처리한다.
- API 연동 이후에도 시연용 데이터 초기화 흐름은 개발 환경에서만 사용할 수 있게 유지한다.

### P3: 모바일 반응형

- PC 웹 MVP 검증 후 동일 플로우를 모바일 웹에 맞춘다.
- 좌측 탐색은 모바일에서 상단 메뉴 또는 하단 탭으로 전환한다.
- 방 목록, 방 상세, 세션 타이머, 완료 기록 폼은 좁은 화면에서도 주요 CTA와 입력값이 잘 보이게 조정한다.
- 세션 화면은 `스마트폰을 내려놓고 읽기` 컨셉에 맞게 집중형 UI로 조정한다.

### P4: 앱 전환 및 고도화 검토

- 모바일 웹 검증 후 PWA 또는 React Native 전환을 비교한다.
- 앱 전환 시 우선 검토 기능은 푸시 알림, 백그라운드 이탈 감지 한계, 세션 리마인드, 홈 화면 추가다.
- 이후 개선 순서는 반복 사용 강화, 실시간 독서방, 외부 도서 검색, 신뢰도/추천으로 둔다.

## Acceptance Criteria

- P0: PC 웹에서 닉네임 입력부터 빠른 시작, 세션 완료, 기록 확인까지 백엔드 없이 완주 가능하다.
- P1: 사용자가 빈 방 상태에서도 무엇을 해야 할지 명확히 알 수 있고, 혼자 써도 함께 읽는 서비스처럼 느껴진다.
- P2: 동일 플로우가 실제 API 데이터로 동작하고, 새로고침 후에도 서버 기준 상태가 유지된다.
- P3: P0~P2의 핵심 플로우가 모바일 웹에서도 깨지지 않는다.
- 제품 성공 기준은 `14일 내 3회 이상 독서 세션 완료`로 둔다.

## Assumptions

- 1차 구현과 시연은 PC 웹 기준이다.
- 모바일 반응형과 앱 전환은 MVP 검증 이후 단계로 둔다.
- P0/P1에서는 백엔드가 없어도 프론트 개발과 UX 검증이 가능해야 한다.
- 실시간, 외부 도서 검색, 신뢰도/추천은 MVP 필수 구현에서 제외한다.
